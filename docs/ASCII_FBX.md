# ASCII FBX 导入说明

适用：BomberStudio Blender Bridge 1.0.1 及之后版本；当前统一安装包为 1.0.2。

## 出现 `ASCII FBX files are not supported`

FBX 有文本（ASCII）和二进制两种存储形式。遇到原生导入器拒绝文本 FBX 时：

1. 在首选项中确认 BomberStudio 插件已启用，当前版本为 1.0.2。
2. 磁盘更新插件后，保存工作并重启 Blender。
3. 使用 **BomberStudio → 导入 BomberStudio 模型**，选原始 FBX。
4. 插件先读取并转换 ASCII，在当前场景设置的临时目录生成二进制缓存，再交给对应版本的原生 FBX 导入器。
5. 查看成功提示，以及临时目录中的 `last-import.json`。
6. 在大纲、形态键和动画编辑器中检查结果。

原文件不覆盖、不改名、不移动。**Blender 自带的 FBX 菜单不经过本插件转换**；使用自带入口时，选择转换好的二进制副本。

## 骨骼兼容与数据保留

部分 Unity FBX 包含 `Root`、`Null`、`LimbNode` 混合骨骼链；只改文件格式，仍可能在 `Root_M` 的蒙皮绑定阶段失败。

本插件会在转换副本中：

- 将实际参与蒙皮的 Root / Null，以及骨骼之间必要的中间节点，规范为骨骼类型；
- 保留节点 ID、连接、矩阵、权重、UV、形态键和动画曲线；
- 不把骨架之外的整个包装层都转为骨骼；
- 保留 `KeyAttrDataFloat` 插值记录的整数位模式；
- 从原始模型路径寻找材质旁文件与图片，不误用缓存目录；
- 导入失败时清理本次新建的场景对象，保留导入前已有对象。

## 缓存与诊断

```text
临时目录/
├── ascii-fbx/
│   ├── 模型名-内容标识.fbx
│   └── 模型名-内容标识.json
├── last-import.json
└── bomberstudio.log
```

源路径、源文件 SHA256 与转换器版本用于区分缓存；缓存二进制也检查 SHA256。损坏缓存保留为诊断副本并重新生成。

`last-import.json` 的 `fbx_conversion` 包含转换状态、版本、文件哈希、节点统计、缓存命中和骨骼规范化记录。

## 验证与范围

1.0.1 的真实 ASCII 样本曾在六个 Windows x64 Blender 版本导入成功，检查到 6 个网格、348 根骨骼、8 个非 Basis 形态键和动画。1.0.2 保留同一转换器；本版重新验证的项目见 [兼容验证](./兼容验证.md)。

- 文本格式版本：FBX 7100～7700；6.x 不在范围内。
- 单文件上限：512 MiB；另有数组、节点、嵌套深度限制。
- 不安装外部 FBX SDK，不执行资产目录内的脚本，不上传模型。
- 没有图片引用的文件不会凭空恢复贴图。
- 转换成功不代表所有第三方 FBX 约束、Shader、控制器或专有特性完全重现。
