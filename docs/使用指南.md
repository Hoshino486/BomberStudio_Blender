# BomberStudio Blender Bridge 详细使用教程

**适用插件：1.1.1｜文档日期：2026-10-03｜示例操作环境：Windows**

1.1.1 已修复完整 GitHub 仓库地址检查，操作见 [更新检查指南](./更新检查.md)。

本版使用单个 Universal ZIP；所有目录示例请替换为自己的路径。

**1.1.0 新增内置 Source Tools 3.4.3**：完整步骤见 [Source Tools 使用指南](./SourceTools.md)。内置提供者仅在 Blender 4.1+ 加载，旧版仍保留原有功能。

本教程按当前插件源码中的实际面板、按钮和参数编写，带你完成：

**安装插件 → 准备 BomberStudio 导出文件 → 导入 Blender → 修复贴图 → 整理模型 → 制作图集/角色功能 → 导出 → 检查与回滚。**

文中的 `角色A`、`Body`、`Head` 等是操作示例。请替换为你自己的文件名或模型中真实存在的名称。教程中的示例工作目录不会因为阅读本文而自动创建。

> 第一次使用：依次阅读第 1～7 章，再按需要进入第 8 章制作图集，最后按第 18 章导出。不要把“模型处理面板”的所有按钮依次点一遍；它们是针对不同问题的独立工具。

## 1. 先确认版本、文件和功能范围

### 1.1 插件放在哪里

下面是自选下载 / 工作目录示例（不要求存在 E 盘）：

```text
D:\BomberStudioWork
```

下载目录中只需一份 Universal ZIP；下列版本都选择它：

| 你的 Blender 版本 | 选择的安装包 |
|---|---|
| 2.79 | `BomberStudio_Blender_1.1.1_Universal.zip` |
| 2.80～4.1 | `BomberStudio_Blender_1.1.1_Universal.zip` |
| 4.2 及之后，包括 4.5、5.x | `BomberStudio_Blender_1.1.1_Universal.zip` |

**同一个 ZIP 按 Blender 版本走对应安装入口，不需要解压或改包。**不要同时启用旧 Legacy 和新 Extension 两个副本。

如果你使用 Blender 4.5.5，按第 2.2 节用扩展入口安装统一包。

### 1.2 怎样确认 Blender 版本

1. 打开 Blender。
2. 在“帮助 / Help”菜单中打开“关于 Blender / About Blender”，或查看启动画面中的版本号。
3. 记下完整版本，例如 `4.5.5`，不要只记“最新版”。
4. 对照上表确定安装入口，始终使用同一个 Universal 包。

本地验证记录实际测试了 Windows x64 的 **2.79b、3.2.2、4.0.2、4.1.1、4.5.5 LTS、5.2.2 LTS**。其他中间版本有兼容代码，但没有逐版实测；2.78 及更早、未来版本以及其他操作系统不属于已验证范围。

### 1.3 需不需要先安装其他插件

- **不需要先装 Cats、MIMIBlender 或 Material Combiner**，本插件的模型整理、图集、口型等功能是独立实现。
- FBX、OBJ、glTF 使用对应 Blender 导入器；某个导入器未提供或未启用时，该格式会提示错误。
- 导入 **PMX/PMD** 需要另外安装与当前 Blender 匹配的 `mmd_tools`。
- 导入 **VRM** 需要另外安装与当前 Blender 匹配的 VRM 导入插件。
- Blender 4.1+ 的 SMD / VTA / DMX / QC 支持已随包内置，无需另装 Source Tools；已有独立版则复用。
- 正常安装和使用本插件不需要运行终端、安装系统 Python 或执行 `pip`。

### 1.4 先知道这几项边界

1. 插件读取 BomberStudio 已导出的模型、材质描述和缓存；不是在 Blender 中直接打开 Unity 资源包的解包器。
2. 材质修复主要恢复贴图、UV、平铺、偏移和 Alpha 使用方式，不等于复原游戏所有专有 Shader。
3. 图集处理常规图片/常量材质，不会自动把任意程序节点、游戏遮罩打包方式转换成标准 PBR。
4. “根据顶点组生成基础骨骼”不等于人体自动绑定；“附加网格”也不会凭空生成蒙皮权重。
5. 口型由已有三个形态键混合，不是语音识别或录音自动对口型。
6. 眼球工具是 Blender 端骨骼辅助，不会自动替你设置 Unity 中的 VRChat Avatar Descriptor。

## 2. 安装、启用插件并找到面板

### 2.1 安装前

1. 保存正在编辑的 `.blend`。
2. 如果已经安装过本插件，在首选项搜索 `BomberStudio`，确认当前装的是哪一种格式。
3. 第一次安装按下面版本流程操作；已安装后的本地 ZIP 更新见第 19 章。
4. **直接选择 ZIP，不必解压，不要把整个“blender插件”文件夹重新压缩后安装。**

### 2.2 Blender 4.2+：通过扩展入口安装统一包

1. 点击主窗口左上角 **编辑 / Edit → 首选项 / Preferences**。
2. 找到 **扩展 / Get Extensions** 或 **插件 / Add-ons** 页面。
3. 打开页面右上角的下拉菜单。
4. 选择 **从磁盘安装 / Install from Disk**。具体中文菜单名可能随界面翻译略有不同。
5. 在文件选择窗口进入：

   ```text
   D:\BomberStudioWork
   ```

6. 选择 `BomberStudio_Blender_1.1.1_Universal.zip`。
7. 确认安装。如果安装窗口带有“安装后启用”选项，勾选它。
8. 在插件列表搜索 `BomberStudio`。
9. 确认 **BomberStudio Blender Bridge** 处于启用状态。
10. 如果首选项没有启用自动保存，使用首选项中的“保存首选项”按钮。
11. 关闭首选项，回到主窗口。
12. 将鼠标放到 **3D 视图**，按 **N**。
13. 在右侧栏找到 **BomberStudio** 标签并点击。
14. 展开 **BomberStudio · 快速访问**。

**成功标志：**看到“导入 BomberStudio 模型”“导入 BomberStudio PC2 物理缓存”“导出 FBX”等按钮。

从磁盘安装本地 ZIP 不依赖公开扩展商店。本插件也没有要求在安装时填写网络密钥。

### 2.3 Blender 2.80～4.1：通过插件入口安装统一包

1. 点击 **编辑 → 首选项 → 插件**。
2. 点击 **安装 / Install**。
3. 进入插件交付目录。
4. 选择 `BomberStudio_Blender_1.1.1_Universal.zip` 并确认。
5. 搜索 `BomberStudio`，勾选 **BomberStudio Blender Bridge**。
6. 按需保存首选项。
7. 回到 3D 视图，鼠标放在视图内，按 **N**。
8. 点击右侧 **BomberStudio** 标签。

**成功标志：**同样出现“快速访问”和其他中文面板。

### 2.4 Blender 2.79：安装统一包

1. 点击 **文件 / File → 用户设置 / User Preferences**。
2. 切换到 **插件 / Add-ons**。
3. 点击 **从文件安装 / Install Add-on from File**。
4. 选择 `BomberStudio_Blender_1.1.1_Universal.zip`。
5. 搜索并勾选 **BomberStudio Blender Bridge**。
6. 按需点击 **保存用户设置 / Save User Settings**。
7. 回到 3D 视图，鼠标放在视图内，按 **T**。
8. 在左侧工具架中找到 **BomberStudio**。
9. 使用节点材质时，将渲染引擎设为 **Cycles**；用渲染预览检查材质。

**注意：**2.79 的入口在左侧 T 工具架，不是右侧 N 插件栏。

### 2.5 已启用却看不到面板

按顺序检查：

1. 当前区域是不是 **3D 视图**，而不是 UV 编辑器、着色器编辑器或图片编辑器。
2. 鼠标是否放在 3D 视图内再按 N/T。
3. 右侧/左侧标签是否被挤到下方，需要滚动才能看到。
4. 插件列表是否确实处于启用状态。
5. 是否同时装了两份插件；保留一份，保存工作后重启 Blender。
6. 如果启用时弹出异常，记录版本、ZIP 文件名和完整错误，不要只截“安装失败”四个字。

## 3. 必学：选中、活动物体、模式与活动材质

### 3.1 “选中网格”不是“选中骨架”

大多数模型和贴图按钮处理的是**当前选中的网格物体**。

1. 在右上角大纲视图（Outliner）找到身体、头发、衣服等网格。
2. 点击一个网格名称；需要多个时按住 Shift 继续选择。
3. 观察物体属性或大纲中的类型图标，确认选的是网格而不是 Camera、Light、Empty 或 Armature。
4. 只选择骨架后点击贴图/顶点组工具，会提示“请先选中网格物体”。

第一次测试一个按钮时，先选择一个网格，确认结果后再处理整批。

### 3.2 “活动物体”是什么

活动物体是当前选择集合中的主对象，通常是**最后选中的那一个**。它会显示在属性编辑器中；高亮颜色随主题不同。

三处特别重要：

| 操作 | 活动物体应是什么 |
|---|---|
| 按位置匹配顶点组名称 | 名称正确、供其他网格参考的网格 |
| 合并骨架 | 最终希望保留下来的目标骨架 |
| 创建口型 | 实际含嘴部形态键的脸部网格 |

稳妥的选择方法：取消选择 → 先选要处理的对象 → 最后 Shift 选择参考/目标对象 → 核对属性编辑器显示的名称。

### 3.3 物体、编辑、姿态三种模式

- **物体模式 / Object Mode**：导入、贴图、图集、多数模型整理、导出。
- **编辑模式 / Edit Mode**：查看顶点、UV，或选择骨骼以设置父级。
- **姿态模式 / Pose Mode**：测试骨架、选择子骨骼、查看角色变形。

开始一次普通处理前，先在 3D 视图左上角切回 **物体模式**。插件会在部分操作中切换模式，但不要依赖所有按钮都能修复任意错误上下文。

### 3.4 “活动材质”是什么

一个身体物体可能同时有皮肤、衣服、眼睛等多个材质槽。

1. 选中网格。
2. 打开右侧属性编辑器的 **材质属性 / Material Properties**。
3. 在材质槽列表中点击想要修改的那一行。
4. 这行对应的就是活动材质。

“应用贴图到选中物体的活动材质”只替换每个选中网格当前活动槽的基础色，不是自动识别并替换全身所有材质。

### 3.5 看材质时切换显示模式

- Blender 2.80+：使用 3D 视图右上角的 **材质预览 / Material Preview** 或 **渲染 / Rendered**。
- Blender 2.79：本插件节点材质建议在 **Cycles 渲染预览**中检查。
- “实体 / Solid”显示为灰色，不足以判断贴图是否导入成功。
- 灯光、世界环境和色彩管理会影响显示；比较图集前后时应保持这些条件一致。

## 4. 设置工作目录并保存第一份备份

### 4.1 设置临时目录

1. 展开 **设置与诊断**。
2. 找到 **临时 / 日志 / 备份目录**。
3. 确认内容为：

   ```text
   D:\BomberStudioWork\临时文件夹
   ```

4. 点击 **打开日志 / 临时文件夹**。
5. 确认资源管理器打开的是这个目录。

### 4.2 设置图集输出目录

1. 展开 **贴图合并 · 材质图集**。
2. 找到 **图集输出目录**。
3. 默认位置：

   ```text
   D:\BomberStudioWork\输出
   ```

4. 有多个项目时，可以改为该目录下的角色专用子目录，例如 `输出\角色A`。
5. 目录可以由图集操作创建，但所在磁盘应存在且可写。

### 4.3 保存工作文件

建议自己建立一个工作目录，并按阶段保存。下面是示例，不是插件固定创建的文件：

```text
D:\BomberStudioWork\工作模型\角色A\
    01_刚导入.blend
    02_材质已修复.blend
    03_角色工具处理后.blend
    04_图集完成.blend
    05_待导出.blend
```

操作：

1. 导入检查完成后，点击 **文件 → 另存为**。
2. 保存为 `01_刚导入.blend`。
3. 每完成一个重要阶段，再另存为下一阶段名称。
4. 不要每次都覆盖唯一的初始文件。

### 4.4 使用插件的手动备份

1. 打开 **设置与诊断**。
2. 点击 **保存模型回滚副本**。
3. 打开临时目录中的 `backups` 子目录。
4. 确认出现带时间和 `manual` 的 `.blend` 文件。

插件保存的是当前场景的副本，不会把当前工作文件切换成备份文件。

### 4.5 自动备份开关的实际作用

**修改前保存 .blend 回滚副本**默认关闭。

打开后会对模型处理、多数角色处理，以及关闭“保留原模型”时的图集修改执行相应备份。**导入、贴图操作、预览和外部文件写入并非都由这个开关覆盖。**重要操作前仍可手动点一次“保存模型回滚副本”。

`.blend` 备份也不等于把外部贴图和 PC2 缓存全部打包；原始导出目录、图集图片、缓存文件都应保留。

这些路径和开关保存在当前场景的 `.blend` 中，不是每个新文件都自动继承的全局配置。打开别的 `.blend` 后请重新检查。

## 5. 在 BomberStudio 中准备导出文件

### 5.1 先确定要导出什么

优先使用**完整模型/角色层级的 FBX 导出**，而不是只导出一张 Texture2D 或一段原始 Mesh 数据。

本机 BomberStudio 源码中有以下入口名称：

- `Export options`：导出选项。
- 模型列表/节点的 `Export selected`：导出所选模型或节点。
- `导出模型+关联动画 / Export model + related animations`：模型及关联动画。

具体菜单位置随 BomberStudio 构建版本可能变化。本文按“已在 BomberStudio 加载到目标模型”开始，不把某一个资源类型的右键菜单当成所有模型通用入口。

### 5.2 建议的导出选项

1. 在 BomberStudio 打开 **Export options**。
2. 找到 **Fbx** 分组。
3. 根据目标勾选：

   | 源码中的选项名 | 什么时候勾选 |
   |---|---|
   | `Export materials` | 需要材质和贴图信息时 |
   | `Export skins` | 需要骨架蒙皮时 |
   | `Export blendshape` | 后续要处理表情、口型时 |
   | `Export animations` | 需要动作时 |

4. 需要导出 Texture2D 时，可启用 `Convert Texture2D` 并选择 PNG，便于检查图片。
5. 确认源端的 `ScaleFactor`，不要同时在源端和 Blender 导入端随意叠加缩放。
6. 选择目标模型，执行对应的模型导出操作。
7. 将一次导出的模型及其依赖保存在同一个项目目录。
8. 等待 BomberStudio 显示导出完成，再进入 Blender。

### 5.3 文件应该如何摆放

下面是**结构示意**。贴图可能直接位于 FBX 同目录，也可能位于导出端提供的子目录；以实际输出及 JSON 引用为准，不要照图随意搬动文件。

```text
角色A_导出目录\
├─ 角色A.fbx
├─ 角色A.fbx.genshin.json     ← 对应适配器可能生成的旁文件之一
├─ Body_Diffuse.png          ← 同目录贴图示例
├─ Hair_Diffuse.png
├─ DedupedTextures\          ← 如果这次导出提供了此目录，则保留
│  └─ ...
└─ Materials\                ← 如果导出材质生成了此目录，则保留
   └─ ...
```

识别的四种旁文件后缀为：

```text
角色A.fbx.genshin.json
角色A.fbx.starrail.json
角色A.fbx.hi3.json
角色A.fbx.zzz.json
```

这不是要求四种文件同时存在，而是按对应导出适配器读取实际存在的文件。

### 5.4 文件名和相对位置不要随意改动

1. 只把 `角色A.fbx` 改名、旁文件还叫旧名字，会导致自动发现失败。
2. `Materials` 原始 JSON 是补充记录，不等于上述 `.fbx.*.json` 自动绑定旁文件。
3. 同一目录树中出现多张同名但不同内容的图片，可能产生匹配歧义。
4. 建议复制整个导出目录作为工作副本，再导入工作副本中的 FBX。
5. 不要把导出目录里的 Python 文件当成普通模型打开；PC2 有独立 JSON 导入入口，见第 17 章。

## 6. 导入模型并检查材质、骨架、动画

### 6.1 导入 FBX

1. 打开 Blender，新建或打开一个用于此角色的工作文件。
2. 如默认立方体等无用对象会干扰选择，可在确认名称后删除；不要在已有项目中无差别清空场景。
3. 切到 **物体模式**。
4. 打开 **BomberStudio · 快速访问**。
5. 点击 **导入 BomberStudio 模型**。
6. 在文件选择窗口定位到刚才的完整导出目录。
7. 选择目标 `.fbx`，不是材质 JSON 或图片。
8. 展开文件选择器中的操作选项区，确认：

   | 参数 | 第一次导入建议 |
   |---|---|
   | 导入比例 | `1.0` |
   | 导入动画 | 有动画需求时开启；默认开启 |
   | 读取 BomberStudio 材质旁文件 | 开启 |
   | 动画帧偏移 | `1.0` |
   | 自动骨骼方向（可能改变绑定，默认关闭） | 关闭 |

9. 点击确认导入。
10. 等待状态提示，不要在处理中连续重复点击。

文件选择器可多选模型；首次排错建议**一次一个**。多文件导入的 `last-import.json` 只保留最后一个模型的当前报告，汇总线索看日志。

### 6.2 检查网格和骨架

1. 在大纲视图检查新增对象。
2. 选中一个身体网格，确认属性编辑器里存在网格数据。
3. 打开 **修改器 / Modifiers**，如果应有骨架，检查 `Armature` 修改器是否指向正确骨架。
4. 在 **物体数据属性 / Object Data Properties** 中查看顶点组、UV 和形态键。
5. 如果导出时应有表情，确认形态键列表不是只有 `Basis`。
6. 如果应有蒙皮但没有骨架/权重，回 BomberStudio 检查 `Export skins` 和导出对象范围；不要直接删除顶点组后重试。

### 6.3 检查贴图

1. 切换到 **材质预览**。
2. 观察身体、头发、脸部、眼睛。
3. 出现粉色/紫色：先按第 7.3 节修复路径。
4. 出现透明洞或脸发黑：先按第 7.2 节检查 Alpha 与图片类型。
5. 花纹位置错位：检查材质要求的 UV 层以及源端 Scale/Offset，不要直接重新展开原模型 UV。

旁文件会保留源材质记录，并根据已有网格的实际 UV 层索引建立节点。缺少 UV 层、同材质跨对象 UV 层名称不一致等情况会记录为待检查项。

### 6.4 检查动画

1. 拖动下方时间轴到不同帧。
2. 检查角色是否按预期运动。
3. 观察脸部、衣服等是否跟随骨架。
4. 如果没有动作，先确认源文件确实含动画，再确认导入时“导入动画”已开启。
5. 如果是帧数整体偏一帧，查看“动画帧偏移”，不要先认定蒙皮损坏。

**帧偏移的选择：**

- BomberStudio 中以零秒开始的源动画，一般使用 `1` 映射到 Blender 第 1 帧。
- 用本插件把 Blender 场景导出，再导回 Blender 做逐帧数值对比时，使用 `0`。

“自动骨骼方向”默认关闭是为了避免不必要地改变导入绑定方向；骨头显示姿态不漂亮，不等于绑定数据坏了。

### 6.5 查看导入报告

1. 在 **设置与诊断** 点击 **打开日志 / 临时文件夹**。
2. 打开：

   ```text
   D:\BomberStudioWork\临时文件夹\last-import.json
   ```

3. 重点看：

   | 字段 | 含义 |
   |---|---|
   | `model` | 本次记录对应的模型路径 |
   | `objects` | 导入创建的对象数 |
   | `bound` | 根据旁文件完成的贴图绑定数，不是材质总数 |
   | `relinked` | 修复的已有图片路径数 |
   | `missing` | 缺失、歧义或其他待检查项目 |
   | `sidecars` | 实际读取的旁文件，存在相应记录时显示 |

4. 出现待检查项不一定意味着整个模型导入失败，应逐项检查。
5. 确认后另存为 `01_刚导入.blend`。

### 6.6 导入其他格式

仍使用 **导入 BomberStudio 模型**，选择 `.obj`、`.glb`、`.gltf`、`.pmx`、`.pmd` 或 `.vrm`。

- OBJ 通常不携带完整骨架动画；“OBJ 导入后没有骨架”本身不是插件异常的充分依据。
- PMX/PMD 报导入器未启用时，先在首选项检查 `mmd_tools`。
- VRM 报错时，检查 VRM 导入插件及其 Blender 版本要求。
- 这些格式能否携带表情、骨架和动画取决于文件格式及对应导入器，不是所有导入选项对每种格式都等效。

---

### 6.7 遇到 ASCII FBX：自动识别与转换

1. 先确认“检查版本更新”面板当前版本为 `1.1.0`；刚更新磁盘文件时，保存并重启 Blender。
2. 用 **导入 BomberStudio 模型** 选择原始 ASCII `.fbx`。
3. 仍保留原导入比例、动画和骨骼方向设置；不需要自己改文件扩展名。
4. 插件将 ASCII 7.1～7.7 转换到当前临时目录的 `ascii-fbx` 子目录，然后自动导入。
5. 提示中会显示 ASCII 自动转换数量；`last-import.json` 的 `fbx_conversion` 包含缓存、源哈希和骨架兼容处理记录。
6. 检查实际网格、形态键、蒙皮和动画，再保存场景。

原 FBX 不覆盖、不移动。此版本还处理混合 Root/Null 骨骼链，避免部分 Unity 导出角色在格式转换后又出现 `KeyError: Root_M`。

自动转换只接在 BomberStudio 的导入按钮上，不替换 Blender 自带 FBX 菜单。已导入场景不靠缓存文件逐帧回放；缓存删除后再次导入会重新转换。PC2 则不同，它的外部缓存必须保留。

范围为 ASCII 7100～7700、单文件不超过 512 MiB；更旧格式需在源软件导出为 FBX 7.x。贴图不会因为格式转换而自动从不存在的数据中补出来。

## 7. 快速预览贴图、处理透明问题、修复丢图

### 7.1 手动给某个材质上基础色

适用场景：模型有 UV，但自动绑定没选到你想要的基础色图片。

1. 选中要处理的网格。
2. 打开材质属性，选择正确的**活动材质槽**。
3. 展开 **快速上预览贴图**。
4. 在 **贴图 / DedupedTextures 目录**选择导出目录或它的 `DedupedTextures` 子目录。
5. 点击 **读取 DedupedTextures / BomberStudio 贴图**。
6. 查看提示中的图片数量。
7. 在列表中点击一张图片。
8. 查看缩略预览，确认它是所需基础色，而不是法线图、遮罩或光照数据图。
9. 初次处理普通不透明身体材质时，保留 **忽略基础色 Alpha（防止数据通道变透明）**。
10. 点击 **应用贴图到选中物体的活动材质**。
11. 切到材质预览，检查结果。

**成功标志：**选中网格的活动材质显示对应图片。没有材质时插件会创建材质；材质由多个用户共享时会先复制，减少对其他未选对象的影响。

多个对象同时选中会使用同一张图片，分别作用到它们自己的活动材质。若身体和头发需要不同图片，请分开操作。

### 7.2 Alpha 开关怎样用

某些游戏贴图的 Alpha 保存的是数据，并不是透明度。把它接到材质透明度，可能让脸、身体或衣服出现不合理透明。

**普通不透明表面：**

1. 选择正确的基础色图片。
2. 勾选“忽略基础色 Alpha”。
3. 重新点击应用按钮。
4. 对比之前的透明区域。

**明确需要透明的头发卡片或类似材质：**

1. 确认图片确有正确透明通道。
2. 取消该开关。
3. 重新应用。
4. 检查透明边缘和渲染效果。

该开关不是“一键修复所有黑脸”。贴图选错、法线错误、灯光和 Shader 差异也要分别排查。

### 7.3 修复缺失贴图路径

适用场景：已经有图片节点，但模型搬家后图片路径失效。

1. 选中需要修复材质的网格。
2. 将“贴图 / DedupedTextures 目录”设置为图片现在实际所在的目录。
3. 点击 **修复缺失贴图路径（精确文件名匹配）**。
4. 查看“重新定位”和“缺失/歧义”数量。
5. 重新进入材质预览，等待图片刷新。
6. 有歧义时，打开 `bomberstudio.log` 查具体文件名。
7. 将搜索目录缩小到正确模型的贴图目录，再重试；不要随便删掉其他模型的同名图。

此操作修复已有但失效的图片引用，不会根据衣服颜色猜测贴图，也不会给完全没有图片节点的材质自动生成全部 PBR 接线。后者用第 7.1 节或材质旁文件导入处理。

### 7.4 LOD 筛选和清空列表

- `LOD` 下拉框按文件名/目录标签筛选 `LOD0`～`LOD8` 及“未标记”。
- 这个筛选**只改变图片列表，不会切换模型网格的 LOD**。
- 更改筛选后，要再次明确点击可见的目标图片，避免沿用之前选中的图片项。
- 点击“刷新”会重新扫描。
- **设置与诊断 → 清空贴图列表与预览**只清空列表和预览指针，不删除磁盘图片，也不撤销已经应用的材质。

## 8. 从零制作贴图图集：完整步骤与参数

### 8.1 图集会做什么

图集把多个材质使用的图片区域排进同一张大图，并为相应面建立新的 UV。默认创建模型副本，原物体隐藏而不删除。

**三个不同按钮不要混淆：**

| 按钮 | 作用 |
|---|---|
| 合并相同材质 | 去重相同材质绑定，不制作新大图 |
| 合并贴图 | 输出图集、改写对应副本的 UV/材质 |
| 合并选中网格 | 将多个网格对象连接为一个对象 |

做完图集不代表场景自动只剩一个网格，也不代表任意情况下绘制开销都完全相同。

### 8.2 处理前准备

1. 确认模型在材质预览中已经显示正确。
2. 保存 `02_材质已修复.blend`。
3. 确认参与处理的每个网格都有 UV。
4. 选择要合并材质的网格，先用两三个普通材质试做。
5. 打开 **贴图合并 · 材质图集**。
6. 点击 **生成材质列表**。
7. 查看列表，取消不想合并的材质。
8. 如果你改变了模型选择或材质槽，再点一次“生成材质列表”，然后重新检查勾选。

对透明、复杂节点、特殊眼睛 Shader，建议先单独检查。不是必须把全身所有材质塞进同一个图集。

### 8.3 首次操作用这些参数

| 界面参数 | 首次建议 | 解释 |
|---|---|---|
| 统一贴图尺寸 | 开启 | 对有基础色图片的材质统一区域最长边 |
| 最长边 | `1024` | 每个贴图区域的最长边，不是最终整张图集边长 |
| 根据 UV 边界裁剪 | 开启 | 按材质实际使用的 UV 范围生成区域 |
| 禁用抗锯齿缩放（最近邻） | 关闭 | 默认使用双线性采样；像素风需求再开最近邻 |
| 图集 PBR 贴图 | 首次可关闭 | 关闭只生成基础色；材质需要 PBR 时看第 8.6 节 |
| 纯色纹理尺寸 | `32` | 没有基础色图片的纯色材质区域尺寸 |
| 纹理间距 / 边缘扩展 | `4` | 区域外侧扩展像素，减少远处采样串色 |
| 图集尺寸 | 正方形（2 的幂） | 边长按打包结果确定 |
| 打包算法 | 二叉树 | 另一选择是行架 |
| 输出格式 | PNG | 也可选 TGA |
| 图集最大边长 | `4096` | 打包上限，不是强制输出尺寸 |
| 创建副本并保留原模型 | 开启 | 首次操作务必保留 |
| 图集输出目录 | 默认“输出”或角色子目录 | 保存图片和 `atlas.json` |

“统一贴图尺寸”保留长宽比，不会把每块贴图都拉成正方形。调整最长边也可能放大较小图片，并不增加它的真实细节。

### 8.4 点击合并并检查结果

1. 再确认当前选择仍是要处理的网格。
2. 点击 **合并贴图**。
3. 等待“图集完成”提示，记录尺寸和通道数。
4. 在大纲视图找到 `BomberStudio_Atlas` 集合。2.79 使用相应组/对象组织方式。
5. 查看名称以 `_Atlas` 结尾的新物体。
6. 在网格数据中检查新增 UV 层 **`BomberAtlasUV`**。
7. 在材质属性中查看 **`BomberStudio_Atlas`** 材质；重复操作后名称可能带数字后缀。
8. 切到材质预览，检查脸、接缝、透明边缘和高光。
9. 打开图集输出目录，进入本次新建的 `Atlas_日期_时间_标识` 子目录。
10. 确认有图像文件和 `atlas.json`。
11. 保存为 `04_图集完成.blend`。

基础色模式的输出示意：

```text
输出\Atlas_日期_时间_标识\
├─ BomberAtlas_BASE.png
└─ atlas.json
```

`atlas.json` 记录输出尺寸、通道、文件路径、材质对应矩形和原 UV 范围。不要只移动 `.blend` 而丢下图集图片。

### 8.5 怎样比较原模型和图集模型

1. 找到原物体，它通常保留原名称但已隐藏。
2. 暂时隐藏 `_Atlas` 副本，显示原物体。
3. 保持相同视角、灯光、色彩管理，观察细节。
4. 再隐藏原物体，显示 `_Atlas` 副本，对照检查。
5. 不要让两者同时重叠显示，否则可能出现闪烁，看起来像贴图坏了。
6. 原物体还会被关闭渲染可见性；需要渲染它时，在大纲的限制列中同时恢复相机图标。
7. 检查完成后，只保留最终要导出的对象处于选择状态。

### 8.6 制作 PBR 五通道图集

在源材质已经正确的前提下：

1. 保存一个图集前版本，或恢复显示原模型并重新选择原模型。
2. 检查材质节点使用 **Principled BSDF**。
3. 基础色、粗糙度、金属度和发光使用直接图片或常量。
4. 法线使用 **Image Texture → Normal Map → Principled Normal**，切线空间、强度 `1.0`。
5. 各通道引用同一套 UV；可以有受支持的简单缩放与偏移。
6. 勾选 **图集 PBR 贴图**。
7. 重新生成/核对材质列表。
8. 点击“合并贴图”。
9. 检查五张图：

   ```text
   BomberAtlas_BASE.png
   BomberAtlas_ROUGHNESS.png
   BomberAtlas_METALLIC.png
   BomberAtlas_NORMAL.png
   BomberAtlas_EMISSION.png
   ```

10. 在材质预览中检查凹凸、高光和发光，不要只看基础色。

图集 PBR 不是把游戏的 `_MaskMap` 自动拆成正确通道。涂层、透射、次表面、复杂混合或程序纹理也不在五通道复制范围内；应先在材质制作流程中烘焙/简化，再合并。旧版非节点材质做 PBR 前，应先转换为有效的 Principled 节点材质。

### 8.7 尺寸不够、太慢或效果不一致

- 打包失败：把单区域最长边从 `1024` 降至 `512`，或拆成两批材质。
- 图片区域非常多：先尝试合并真正相同的材质，再生成材质列表。
- 单次总面积上限为 **16,777,216 像素**。即使最大边长允许填 `8192`，也不代表 `8192×8192` 可以生成。
- UV 超出 0～1、负 UV、平铺会占用实际区域；不要简单把 UV 截断到 0～1。
- 法线强度不是 1、发光图片还有额外强度变换、不同通道使用不同 UV：按错误提示先烘焙/整理。
- 输出只有基础色时，不要期待原材质所有高光、发光和其他通道一起保留；需要这些数据应使用合适的 PBR 工作流。
- 程序节点、UDIM、序列图片、视频、旋转 Mapping 等会触发不支持提示，反复点击同一参数不会消除这些条件。

### 8.8 如何撤销图集

**保留原模型开启：**隐藏新副本，恢复原物体的视图及渲染可见性；确认不再需要后再自行删除副本。

**保留原模型关闭：**优先立即撤销，或打开图集前 `.blend`/手动备份。这个模式直接修改所选对象，首次使用不建议关闭保留开关。

外部生成的 PNG/TGA/JSON 不会因为 Ctrl+Z 自动删除。确定没有 `.blend` 或 FBX 再引用它们后，才整理对应输出目录。

## 9. 模型整理、法线、修改器和网格合并

### 9.1 本章的共同准备

1. 保存一个 `.blend`，或点击“保存模型回滚副本”。
2. 切到物体模式。
3. 只选择需要处理的网格。
4. 展开 **模型处理面板**，执行下面对应的一项。
5. 检查结果；异常时先撤销，不要叠加其他修复按钮。

### 9.2 重置位置和旋转

**重置模型 x/y/z 位置为 0**

1. 选择网格。
2. 先在变换面板记下当前位置。
3. 点击按钮。
4. 检查物体的 Location 变成 `(0, 0, 0)`。

这是重置物体的**局部位置属性**，有父级时不保证到世界原点；它不是“应用位置”。把有相对偏移的身体和衣服全部归零，可能改变装配关系。

**重置模型 x/y/z 旋转为 0**

1. 选择网格。
2. 点击按钮。
3. 检查欧拉旋转归零，其他旋转表示重置为无旋转。
4. 观察模型朝向是否仍符合需求。

它不是“应用旋转”。已经正确绑定、方向正确的模型不需要为了数值好看而执行。

### 9.3 删除模型中的松散点

1. 选中网格，记下顶点数量，或打开视图统计便于比较。
2. 点击 **删除模型中的松散点**。
3. 检查外形和顶点数量。

当前实现删除的是**不连接任何边，也不连接任何面的孤立顶点**，不是删除所有线框边或所有独立零件。头发、牙齿等独立但有面的部件不会因为“松散点”这个名称就被清掉。

### 9.4 清除自定义拆分法向

1. 保存处理前文件。
2. 选择阴影异常的网格。
3. 点击 **清除自定义拆分法向**。
4. 在同一灯光下旋转视角，比较阴影。
5. 若精细制作的角色脸部反而变差，立即撤销。

该功能清理导入的自定义拆分法向，不是完整的自动修面、朝向修正或游戏面部光照重建。

### 9.5 平滑法线存入 UV

1. 选中网格。
2. 点击 **平滑法线存入 UV（八面体编码）**。
3. 打开物体数据属性中的 UV 列表。
4. 确认出现 **`Bomber_SmoothNormal_Oct`**。
5. 保留原来的贴图 UV，不要把新层误当作基础色展开结果。

新 UV 保存的是物体空间平滑法线的八面体编码，需要相应下游 Shader/导出流程解码。用于普通图片预览时，仍应选原贴图 UV。

同名层已存在时，该工具会更新其中的数据，不会每次自动留下一个旧层备份。

### 9.6 重算 TANGENT / COLOR

1. 选中网格。
2. 按下游流程需要，点击：
   - **向量和归一化重算 TANGENT**；
   - 或 **算术平均归一化重算 COLOR**。
3. 在新版 Blender 的颜色属性中查找 `TANGENT` 或 `COLOR`；旧版在顶点色列表中查看。
4. 在物体自定义属性中检查 `3DMigoto:RecalculateTANGENT` 或 `3DMigoto:RecalculateCOLOR` 标记。

这两个入口当前都写入经过编码的平滑法线颜色数据，RGB 为 `normal × 0.5 + 0.5`。它们不是直接重写 Blender 的 UV 切线及其 handedness，也不包含 3DMigoto 原始缓冲导出器。

已有同名颜色层会被更新。只为普通 FBX 展示模型时，不需要为了“优化”强行执行这两项。

### 9.7 在有形态键的模型上应用修改器

适用场景：模型有表情键，还希望固化某个保持顶点顺序和拓扑的形变修改器。

1. 选择一个网格，先只做单物体测试。
2. 打开修改器列表，记下目标修改器的**实际名称**。
3. 确认它不会增删顶点或面，例如平滑、简单形变等受支持的形变类型。
4. 在 **模型处理面板**底部找到 **修改器名称**。
5. 填入准确名称；留空会尝试处理可见的非骨架修改器。
6. 点击 **在有形态键的模型上应用修改器**。
7. 检查目标修改器是否已从栈中移除。
8. 到形态键列表逐个改变数值，检查 Basis、表情和驱动/动画。
9. 确认顶点、面连接和角色外观符合预期，再保存下一阶段文件。

受支持的形变类型包括 Smooth、Laplacian Smooth、Corrective Smooth、Cast、Simple Deform、Displace、Wave、Lattice、Curve、Shrinkwrap、Hook、Mesh Deform、Surface Deform；最终仍以求值后的顶点数与拓扑检查为准。

**遇到以下提示时：**

- 修改器改变拓扑：不要在保留形态键的原模型上强行应用细分、镜像、焊接或布尔；先在单独的无形态键副本中处理对应需求。
- 前面存在保留的可见修改器：先检查整个栈的求值顺序。不要为了通过检查盲目拖动 Armature 或其他修改器。
- 名称不匹配：使用修改器标题栏中的名称，而不是自行翻译的类型名。

形态键流程保留 Armature 修改器。本插件此按钮不包含独立的“姿态烘焙”功能。没有形态键的模型会走 Blender 常规修改器应用路径。

### 9.8 合并相同材质

1. 选中需要去重材质的网格。
2. 在 **快速访问**点 **合并相同材质**，或在 **优化 · 材质 / 网格 / 骨骼**点 **合并完全相同的材质**。
3. 查看合并计数。
4. 对比处理前后的外观和材质槽。

判断依据包括实际节点、图片、参数和 UV Mapping，不是只看材质名字相似。复杂未知节点、动画材质等可能被跳过；合并数量为 0 不一定是错误。

它不会生成图集 PNG，后续想制作图集仍需使用第 8 章流程。

### 9.9 合并选中网格

1. 保存备份。
2. 选择至少两个网格。
3. 最后选择希望作为主对象的网格，使它成为活动物体。
4. 点击 **合并选中网格**。
5. 检查大纲中的对象数量、材质槽、形态键、修改器和骨架绑定。

这是 Blender 的标准连接操作。不同对象的修改器栈、形态键和绑定结构并不总能无条件合并保留；结构不同的角色部件，应在副本上验证。

此按钮只合并所选网格，不是把场景中所有隐藏物体和骨架全部合成一体。

## 10. 顶点组：清理、排序、补号、合并与名称匹配

### 10.1 先查看顶点组

1. 选择网格。
2. 打开 **物体数据属性**。
3. 找到 **顶点组 / Vertex Groups**。
4. 记录名称形式：是 `0、1、2`，还是 `Head、Hips、LeftEye`。
5. 如果组名与骨骼对应，这些组通常用于蒙皮；随意删名或改名会改变绑定效果。

下面的按钮都在 **模型处理面板**。只执行与你的数据类型相符的那一项。

### 10.2 三种移除操作

| 按钮 | 操作步骤 | 结果与检查 |
|---|---|---|
| 移除所有顶点组 | 保存备份 → 选网格 → 点击 | 所有组和权重绑定删除；仅在确实要重做组数据时使用 |
| 移除未使用的空顶点组 | 选网格 → 点击 → 查看组列表 | 删除没有有效正权重的组；有权重的组保留 |
| 移除非数字名称的顶点组 | 确认这是数字组工作流 → 点击 | 仅保留纯数字名称；`Head`、`2.001` 等会被删除 |

不要在普通人体骨架模型上把“移除非数字名称”当通用清理。它会移除 `Hips`、`Head` 等有用蒙皮组。

### 10.3 根据顶点组名称排序

1. 选择需要整理列表的网格。
2. 点击 **根据顶点组名称排序**。
3. 返回组列表检查顺序。

自然排序会把数字按数值顺序排列，例如 `1、2、10`，而不是 `1、10、2`。这只是整理组顺序，不会自动重命名为连续数字。

### 10.4 填充数字顶点组间隙

1. 确认组名中存在纯数字编号。
2. 点击 **填充数字顶点组间隙**。
3. 检查从 `0` 到最大编号之间缺失的组是否补齐。

例如原来是 `0、2、5`，会补出空的 `1、3、4`。新增组没有自动分配权重。

最大数字编号超过 `10000` 时会停止，避免误创建大量空组。非数字组不因此自动改名。

### 10.5 合并相同数字前缀的顶点组

1. 备份。
2. 确认 `2`、`2.001`、`2_extra` 这类组在你的流程中确实应视作同一个编号。
3. 点击 **合并相同数字前缀的顶点组**。
4. 检查合并后编号组，例如 `2`。
5. 在权重绘制或姿态测试中确认蒙皮没有意外变化。

同顶点权重会累加并限制到 `1`；它不会顺便把该顶点所有其他骨骼组重新归一化。不要把仅仅名称相似但含义不同的组批量合并。

### 10.6 按位置匹配活动物体的顶点组名称

示例：A 网格已有正确组名，B 网格的组名需要对照 A 改名。

1. 保存备份，确认 A、B 在**世界空间**中对应部位重合。
2. 确认两者的顶点组都有有效权重。
3. 取消所有选择。
4. 先选 B，再 Shift 选择 A，使 A 成为活动物体。
5. 在 **位置匹配容差**先用默认 `0.0001`。
6. 点击 **按位置匹配活动物体的顶点组名称**。
7. 查看“已匹配”数量。
8. 检查 B 的组名以及后续绑定结果。

匹配依据是每个组的**世界空间加权中心**，不是逐顶点拓扑对应，也不把 A 的权重复制给 B。

- 没有唯一候选的组会保留原名；匹配数为 0 时先查位置、比例和权重。
- 多个待处理组指向同一目标名时会提示歧义。
- 不要一开始就把容差调很大，否则不同部位可能被当成同一个位置。
- 只改变组名不会自动重命名 B 所属骨架的全部骨骼，改完还需核对组名与绑定关系。

### 10.7 用模型名称作为顶点组前缀

1. 确认要给不同网格的组增加命名空间。
2. 选中网格。
3. 点击 **用模型名称作为顶点组前缀**。
4. 检查名称，例如 `Body_Head`。

权重数值保留，但此操作不配套重命名已有骨架。对已绑定模型使用可能破坏组名匹配。重复执行会继续叠加前缀，不是幂等的“补一个前缀”操作。

## 11. 模型分割与形态键静态快照

### 11.1 选择哪一种分割方式

| 你的目标 | 选择按钮 |
|---|---|
| 按不同材质槽拆对象 | 其他选项中的“材质”（按材质分割模型） |
| 按几何上互不连通的部分拆对象 | “松散块”（按几何松散块分割模型） |
| 沿 UV 接缝分成独立对象 | “UV 岛”或“根据 UV 岛分割模型” |
| 每个面归入权重最大的组 | “按顶点组分割模型” |
| 分开组边界，但仍留在一个对象内 | “根据顶点组拆为松散块” |
| 按几何连通与共享组关系聚类 | “根据共享与孤立顶点组分割”或“按松散块分割并按顶点组聚类” |
| 每个表情变成独立静态网格 | “按形态键生成静态快照” |

当前版本中，两个“共享组/聚类”入口使用相同的连通与可传递共享组聚类逻辑，不要期待它们在所有模型上产生不同结果。

### 11.2 按材质、松散块或 UV 岛分割

1. 保存 `.blend`。
2. 切物体模式，只选中要分割的网格。
3. 使用 UV 岛方式时，先在网格 UV 列表确认**活动 UV 层**是要依据的贴图层，而不是存法线的新 UV 层。
4. 展开 **其他选项 · 分离 / 翻译**。
5. 点击“材质”“松散块”或“UV 岛”。
6. 在大纲中查看以原物体名加 `_Splits` 命名的集合/组。
7. 检查 `_part_000`、`_part_001` 等结果物体。
8. 检查贴图、权重和形态键。

原物体会隐藏保留。恢复时按第 8.5 节同时检查视图和渲染可见性。

若只检测到一个分组，操作可能没有生成新对象，这是“没有可分割的第二组”，不一定是运行失败。超过 `512` 个分组会提示缩小范围。

UV 岛依据实际相邻面 UV 连续性判定，所以同一片连通几何也可能拆成多个 UV 岛；不是只检查模型是否分成独立零件。

### 11.3 顶点组相关分割

**按顶点组分割模型：**

1. 选中有权重的网格。
2. 点击对应按钮。
3. 每个面按其顶点对各组累计权重的最高者归类。
4. 检查结果，不会为了每个重叠权重组复制同一张面。

**根据顶点组拆为松散块：**

1. 先手动备份；这项不是默认“复制多个对象”的流程。
2. 选择网格并点击按钮。
3. 仍保留一个网格对象，但不同主导组之间的边界会被拆开。
4. 进入编辑模式检查边界；想进一步拆成对象，再使用几何松散块分割。

**共享组/聚类：**

1. 选择网格并执行对应按钮。
2. 同一组连接多个区域、不同组之间有传递关系时，它们可能合为一个大分组。
3. 如果预期应有很多碎片却只剩少数对象，先检查权重共享关系，不要直接认为算法漏拆。

### 11.4 按形态键生成静态快照

1. 选中含 `Basis` 和至少一个其他形态键的网格。
2. 保存备份。
3. 点击 **按形态键生成静态快照**。
4. 查看以 `_ShapeSnapshots` 命名的集合/组。
5. 找到每个形态键对应的物体，例如 `Face_AA`。
6. 暂时隐藏其他快照，只显示一个检查外形。

每个快照使用对应形态键存储的坐标，**不是当前所有形态键滑块混合后的烘焙**。快照本身不再保留形态键列表；原物体隐藏保留。

多个快照初始位置相同，同时显示会重叠。超过 `256` 个非 Basis 形态键时，先在副本里缩小处理范围。

## 12. 基础骨架、合并骨架、附加网格和骨骼优化

### 12.1 根据顶点组生成基础骨骼

适用：网格已有权重组，但还没有有效绑定骨架，需要建立基础骨骼对象。

1. 保存备份。
2. 选择有权重组的网格。
3. 确认它们没有绑定现存 Armature；已经绑定的网格会提示先处理副本中的旧绑定。
4. 在 **模型处理面板**设置 **新骨骼长度**，默认 `0.03`。
5. 点击 **根据顶点组生成基础骨骼**。
6. 检查新对象 **`BomberStudio_Rig`**。
7. 查看骨骼名称是否对应顶点组。
8. 检查网格上的 `BomberStudio_Armature` 修改器。
9. 按需要继续设置骨骼父子关系。

新骨骼头部根据组权重中心生成，尾部朝 +Z 延伸；初始不推测人体层级。这里得到的是基础结构，不是真实关节轴、IK 控制器或原始骨架的完整还原。

### 12.2 开始/结束姿态模式

1. 选中骨架，或选中绑定到它的网格。
2. 在 **快速访问**点击 **开始 / 结束姿态模式**。
3. 确认进入姿态模式。
4. 选一根骨骼做小幅旋转，检查网格跟随。
5. 撤销测试旋转，或按你的动画流程复位。
6. 再点同一按钮回到物体模式。

不要把尚未复位的测试姿态当成新静止姿态保存或导出。

### 12.3 重命名 GI / MMD 常用骨骼

1. 选择骨架或绑定网格。
2. 保存备份，并记录外部动画/引擎是否依赖当前骨骼名称。
3. 点击 **重命名 GI / MMD 常用骨骼**。
4. 检查如 `Bip001 Head → Head` 等已知映射。
5. 检查绑定网格的相应顶点组。
6. 播放或测试已有动画，确认引用没有意外变化。

只使用内置常见映射，不保证识别所有游戏、角色和自定义名字。未知名称和冲突目标保留，不会凭空推断全套人体骨名。

### 12.4 合并两个骨架

示例：把配件骨架 B 合到角色骨架 A，A 作为保留目标。

1. 保存包含 A、B 及其绑定网格的 `.blend`。
2. 确认 A、B 在场景中已经对齐。
3. 检查 B 是否含 Action/NLA 动画；有动画时插件会停止合并。
4. 若确实只需 B 的静态骨架，先在独立备份/副本中处理源动画；不要在唯一文件中直接丢弃动画。
5. 回物体模式，取消选择。
6. 先选 B，再 Shift 选 A，使 A 成为活动骨架。
7. 展开 **自定义模型创建**。
8. 点击 **合并骨架**。
9. 检查最终骨架对象、源网格的 Armature 指向以及世界位置。
10. 测试肩、头、配件等部位。

重复骨名会增加源骨架前缀以避免冲突，**不是把两个同名 Head 自动焊成一根骨骼**。此工具也不自动把 B 的动作重定向到 A。

### 12.5 附加网格到骨架：两种不同用途

#### A. 需要随蒙皮变形

1. 确认网格已有与目标骨架骨名对应的权重组。
2. 选择网格，再选择目标骨架，使目标骨架活动。
3. 在 **自定义模型创建**中将 **父骨骼**清空。
4. 点击 **附加网格到骨架 / 骨骼**。
5. 检查网格父对象和 Armature 修改器指向目标骨架。
6. 姿态测试确认变形。

按钮添加/指定绑定关系，不生成自动权重。没有正确组权重时，“附加成功”不代表网格已经能正确弯曲。

#### B. 配件刚性跟随一根骨骼

1. 选择配件网格和目标骨架。
2. 在 **父骨骼**填写目标骨骼真实名称，例如 `Head`。
3. 点击同一附加按钮。
4. 验证配件世界位置没有跳动。
5. 旋转目标骨骼，检查配件整体跟随。

刚性附加不会自动清除网格上原有的蒙皮修改器。若配件原先已经蒙皮，先在副本中决定保留哪种变换方式，避免双重变形。

“父骨骼”字段也用于第 15.1 节的骨骼父级工具。切换用途时请重新确认它的值。

### 12.6 移除无权重末端骨骼

1. 保存备份。
2. 选择骨架。
3. 展开 **优化 · 材质 / 网格 / 骨骼**。
4. 在 **保留末端骨骼（逗号分隔）**填写要保护的骨名。
5. 使用英文逗号，不在逗号后额外加空格，例如：

   ```text
   Head,LeftEye,RightEye,Root,WeaponSocket
   ```

6. 点击 **移除无权重的末端骨骼**。
7. 检查骨架结构和配件挂点。

默认保护 `Head,LeftEye,RightEye,Root`。操作只删除无有效权重、无子骨骼、无相应姿态约束且未被保护的末端骨骼；并非一次性递归移除所有“看起来没用”的骨头。

含 Action/NLA 的骨架会提示先保存并处理动画。只用于外部引擎挂点、脚本或特殊约束链的无权重骨骼应自己加入保护名单。

## 13. 制作和预览 15 个 VRChat 口型

### 13.1 需要什么输入

需要脸部网格上存在三个有效的**相对形态键**，分别能表现 AA、OH、CH 所需基础嘴型。实际名称可以是其他语言，不要求字面就叫 `AA/OH/CH`。

没有形态键时，插件不会从零雕刻出嘴部动作。先确认 BomberStudio 导出包含 `Export blendshape`，并选中真正带嘴部形态键的网格。

### 13.2 创建步骤

1. 保存一个口型生成前的 `.blend`。
2. 选中脸部网格，使它成为活动物体。
3. 打开物体数据属性的形态键列表。
4. 单独把候选源键调到 `1`，观察嘴型，然后恢复 `0`。
5. 展开 **Visemes · 口型**。
6. 在 **Viseme AA** 搜索选择对应基础键。
7. 在 **Viseme OH** 选择圆口基础键。
8. 在 **Viseme CH** 选择对应基础键。
9. **形态键混合强度**先用 `1.0`。
10. 点击 **创建 15 个 VRChat 口型**。
11. 回到形态键列表，确认出现：

   ```text
   vrc.v_sil
   vrc.v_PP
   vrc.v_FF
   vrc.v_TH
   vrc.v_DD
   vrc.v_kk
   vrc.v_CH
   vrc.v_SS
   vrc.v_nn
   vrc.v_RR
   vrc.v_aa
   vrc.v_E
   vrc.v_ih
   vrc.v_oh
   vrc.v_ou
   ```

`vrc.v_sil` 是静音/中性形态，预览它时没有明显变化属于正常情况。

### 13.3 逐个预览

1. 先把原 AA/OH/CH 以及其他会影响嘴部的非测试形态键设回 `0`。
2. 如果有驱动或关键帧控制这些数值，先在工作副本中处理预览冲突。
3. 点击 **预览下一个口型**。
4. 查看提示中的当前口型名称。
5. 检查嘴唇穿插、牙齿暴露、下巴变形和嘴角。
6. 继续点击检查全部口型。
7. 点击 **停止口型预览**。
8. 确认 `vrc.v_*` 数值归零，模型回到中性表情。

预览按钮只清零它管理的 `vrc.v_*` 键，不会自动清零原 AA/OH/CH。源键还保持 1 时，会出现叠加变形。

### 13.4 想重新调强度怎么办

生成后改变“形态键混合强度”不会自动重算已经生成的键。

1. 最稳妥的方法是重新打开生成前备份。
2. 调整强度，如 `0.8`。
3. 再生成一次并比较。
4. 如果要在当前文件重建，先处理已有 `vrc.v_*` 及其驱动/动画，不要直接覆盖唯一数据。

存在任何目标同名键时，生成操作会停止。混合口型只是起点，最终还需按角色造型做美术修正，并在 Unity 对应组件中选择正确网格和口型映射。

## 14. 眼球追踪骨骼：创建、预览与复位

### 14.1 先确认模型结构

至少需要一个可定位的骨架；每只眼睛需要有效眼球权重组，或已经存在对应眼骨。

1. 选中骨架或绑定网格。
2. 检查真实头骨名字，例如 `Head` 或其他名称。
3. 检查左右眼骨/顶点组名字。
4. 左右按**角色自己的左右**理解，不按观察者屏幕左右随意填。
5. 对贴在脸上的眼睛、没有独立眼球权重的模型，先完成对应建模和权重工作。

### 14.2 填写参数并创建

1. 保存备份，结束正在播放的动画。
2. 展开 **Eye Tracking · 眼球追踪**。
3. 在 **眼球模式**选择 **VRChat SDK3** 或 **Legacy**；它们在此均为 Blender 辅助模式标记。
4. 填写：

   | 字段 | 默认值 | 应填内容 |
   |---|---|---|
   | 头部骨骼 | `Head` | 实际头骨名称；有意不设置新眼骨父级时可留空 |
   | 左眼骨骼 | `LeftEye` | 已有或将新建的左眼骨名 |
   | 右眼骨骼 | `RightEye` | 已有或将新建的右眼骨名 |
   | 左眼权重组 | `LeftEye` | 网格中实际左眼组 |
   | 右眼权重组 | `RightEye` | 网格中实际右眼组 |

5. 左右眼骨名应不同。
6. 如需调新骨骼长度，在 **模型处理面板 → 新骨骼长度**设置；默认 `0.03`。
7. 点击 **创建 / 定位眼球追踪骨骼**。
8. 在骨架中检查两根眼骨和网格的相应权重组。

已有眼骨不会为了“居中”被移动静止矩阵。新眼骨按绑定网格中的权重中心创建，尾部按骨架局部 -Y 延伸；实际眼睛方向仍需要你检查。

输入权重组名与目标骨名不同时，工具可能配套改组名；目标组已存在会报冲突。先备份，错误后检查是否已经存在部分变化。

### 14.3 预览与复位

1. **预览旋转角度**先用 `10`。
2. 点击 **预览眼球旋转**。
3. 观察两只眼睛是否正常转动，而不是整张脸被拉动。
4. 改为 `-10` 再测另一方向。
5. 点击 **重置眼球姿态**。
6. 确认眼睛回到预期中性状态。

预览将眼骨设为 XYZ 欧拉，并用 X 轴角度测试；它不是实时视线追踪。复位设置旋转为 0，**不是恢复按钮执行前任意已有的眼部姿态/旋转模式**。有动画的角色请在副本中测试，再恢复动画状态。

导入 Unity 后仍需要自己设置眼球引用、范围和 Avatar Descriptor；本按钮不会生成完整 Unity 配置。

## 15. 骨骼父级、模型身高和 MMD 基础整理

### 15.1 设置骨骼父级

示例：把两根新眼骨设置为 `Head` 的子骨骼。

1. 保存备份。
2. 选中骨架。
3. 进入**姿态模式或编辑模式**。
4. 选择要改父级的子骨骼，例如左右眼骨。
5. 展开 **Bone Parenting · 骨骼父级**。
6. 在 **父骨骼**搜索选择 `Head`，不要误选成某个子骨骼的后代。
7. 点击 **设置选中骨骼的父骨骼**。
8. 操作结束后可能回到物体模式；重新进入编辑/姿态模式检查层级。
9. 确认骨骼头尾位置不变，且没有强制首尾连接。

工具会阻止形成父子循环。这一面板是给**骨骼**设置父级；把帽子等网格挂到 Head，请用第 12.5 节的附加网格功能。

### 15.2 按米设置模型身高

1. 让模型处于用于测量的中性姿态，避免跳跃、蹲下或大幅动作影响高度。
2. 检查场景单位中的 `Scale Length` 是否是项目期望值。
3. 选择目标角色的骨架和网格，排除其他角色、地面和道具。
4. 展开 **Model Scaling · 模型缩放**。
5. 在 **目标身高（米）**输入目标，例如 `1.7`。
6. 点击 **按目标身高缩放模型**。
7. 检查整体尺寸、地面接触和位置。
8. 如果角色离原点很远，重新检查其位置变化是否符合预期。

算法使用所参与网格的世界 Z 轴包围盒高度，并考虑场景单位。它缩放层级根，避免骨架和子网格重复缩放；同时按场景原点缩放根的位置。

注意：

- 选择了绑定网格/骨架时，可能一并纳入这个骨架绑定的其他网格。
- 头发、帽子、鞋跟或外伸部件可能改变包围盒“最高/最低点”；这里不是人体脚底到头顶的语义测量器。
- 它修改 Location/Scale，不自动“应用缩放”。
- 不要操作后再把所有子网格各自缩放一遍。
- 高度为零的平面或退化数据会提示错误。

### 15.3 MMD 基础整理

1. 通过 `mmd_tools` 导入新模型。
2. 保存一份未整理的 `.blend`。
3. 选择此模型的网格及适当的根对象/骨架，排除其他角色。
4. 展开 **MMD 选项**。
5. 确认 **MMD 整理时移除刚体与关节**是否符合需求，默认开启。
6. 点击 **MMD 基础整理**。
7. 检查松散点、空顶点组、平滑面和物理对象。

当前实现是基础清理，不等同于 Cats 历史版本中全部 `Fix Model` 操作，也不会自动修正所有 MMD 约束、骨架轴或 Unity 设置。

### 15.4 单独移除刚体与关节

1. 保存备份。
2. 选择目标模型的根对象、骨架或相关对象，确认其层级范围。
3. 点击 **移除刚体与关节**。
4. 检查大纲中的刚体/关节对象是否移除。
5. 确认别的角色物理仍然存在。

范围包括所选对象、其子层级和找到的绑定骨架子层级；识别 MMD 元数据或 Blender 刚体/约束对象。若未删到，先检查物理对象是否真的属于所选层级，避免直接扩大为整个场景。

该按钮删除物理对象，不是暂时关闭模拟。保留 MMD 物理用途时，应关闭整理中的自动移除选项。

## 16. 离线名称翻译与 CSV 自定义改名

### 16.1 使用内置名称表

1. 保存备份。
2. 选择要改名的网格/骨架。
3. 展开 **其他选项 · 分离 / 翻译**。
4. 在 **翻译范围**选择“全部”“形态键”“骨骼”“物体”或“材质”。
5. 按需要保留 **跳过锁定的形态键**。
6. 如要记录映射，到 **设置与诊断**勾选 **翻译时导出 CSV**。
7. 点击 **离线名称翻译**。
8. 检查名称和绑定，再保存。

骨骼范围需要实际选中骨架；仅选网格不等于遍历其绑定骨架的所有骨骼。形态键的 Basis 不作为普通表情键翻译。

这是内置常见中/日/GI 名称字典，不使用 Google 等在线服务，未知名称保留。共享材质的数据名称被修改时，使用它的其他物体也会看到新名称。

### 16.2 先导出一份 CSV

1. 选择目标对象。
2. 设置翻译范围。
3. 在 **名称映射 CSV**指定文件位置，默认：

   ```text
   D:\BomberStudioWork\名称映射.csv
   ```

4. 点击 **导出名称 CSV**。
5. 用支持 UTF-8 的文本编辑器或表格软件打开。
6. 确认表头为：

   ```csv
   kind,source,target
   ```

导出用于列出当前名称及字典建议，不会立即执行改名。`target` 不一定与 `source` 相同；请检查所有行，而不是只修改自己新增的那一行。

### 16.3 编辑自己的映射

例如：

```csv
kind,source,target
OBJECT,身体,Body
SHAPEKEY,あ,AA
SHAPEKEY,お,OH
SHAPEKEY,ち,CH
BONE,Bip001 Head,Head
```

其中：

- `source` 必须是当前场景中的完整真实名称。
- `target` 是希望使用的新名称。
- 建议从实际导出的 CSV 开始修改，保留表头。
- 保存为 UTF-8；含 BOM 的 UTF-8 也支持。
- 名称中含逗号时，按 CSV 规则用双引号括起来。
- 使用英文逗号分隔列，不要用中文逗号或把 CSV 保存成 Excel 二进制文件。

**当前导入器按 `source → target` 建字典，`kind` 是记录列，不作为独立命名空间过滤。**同一个 source 在文件中重复出现时，后面的映射会覆盖前面的映射。若骨骼和物体同名但需要不同目标名，请分开选择范围、分文件执行。

### 16.4 导入并实际改名

1. 再保存一次备份。
2. 回 Blender，选择需要改名的对象。
3. 设置准确的“翻译范围”，首次不要盲目选“全部”。
4. 确认 CSV 路径指向刚编辑的文件。
5. 点击 **导入名称 CSV 并翻译**。
6. 检查对象、骨骼、材质或形态键名称。
7. 检查外部依赖和动画引用。

这个按钮会立即改名，不是“导入后等待另一次确认”。CSV 映射会叠加到内置字典上；内置字典中已有的其他名称也可能在所选范围中发生转换。

骨骼目标名已存在时会跳过冲突；其他 Blender 数据块可能自动增加数字后缀。最终以场景中的实际名称为准。

## 17. 导入 BomberStudio PC2 物理缓存

### 17.1 这与普通 FBX 导入有什么不同

普通 FBX 常用骨架、蒙皮和形态键驱动；这里读取的是 BomberStudio 导出的逐顶点缓存。

入口是 **导入 BomberStudio PC2 物理缓存**，选择文件是 **`physics-cache.json`**。不要在这个入口选单个 `.pc2`，也不需要运行目录中的 `import_nowind.py`。

它回放已导出的顶点运动，不重新运行游戏原生物理求解器。

### 17.2 准备缓存目录

1. 在 BomberStudio 对应缓存导出功能中完成一次导出。
2. 等待全部帧和清单写入完成。
3. 确认目录中有 `physics-cache.json`，以及清单引用的 `.pc2` 和图片。
4. 保持原相对路径，不单独移动 JSON。
5. 不要手动修改清单中的 SHA256、顶点数或完成标记来绕过错误；数据不完整时应重新导出。

插件读取的清单 schema 是：

```text
BomberStudio.NoWind.VertexCache/1
```

其他软件输出的任意 JSON/PC2 组合，不一定满足这份清单结构。

### 17.3 导入和播放

1. 保存当前工作。
2. 切回物体模式。
3. 在 **快速访问**点击 **导入 BomberStudio PC2 物理缓存**。
4. 选择对应目录的 `physics-cache.json`。
5. 确认导入。
6. 等待“PC2 校验通过”提示。
7. 查看新建的 `BomberStudio_NoWind_…` 集合/组和 `_NoWind` 网格。
8. 在网格修改器中检查 **`BomberStudio_PC2`**，类型为 Mesh Cache。
9. 检查时间轴：起始帧设为 `1`，结束帧和 FPS 来自缓存清单。
10. 拖动到中间帧、最后一帧，观察衣物/角色顶点变化。
11. 保存 `.blend`，并继续保留缓存目录。

清单导入会调整**当前场景**时间范围和 FPS。已有其他动画项目时，最好在独立场景文件中检查缓存。

源端已转换为 Blender Z-up 的数据不会再额外旋转。若模型看起来不对，先查是否重复导入/叠加变换，不要默认再转 90°。

### 17.4 常见缓存问题

| 现象 | 处理步骤 |
|---|---|
| 导出未完成/完成标记异常 | 回源端完成导出，重新选择完整目录 |
| 文件头、大小、帧数或顶点数不符 | 检查文件是否传输截断，重新复制完整导出目录 |
| SHA256 不一致 | 使用与清单同一次导出的 PC2，避免旧 JSON 配新缓存 |
| 面索引/UV 校验失败 | 不在文本编辑器里凑数；保留报告并重新检查源导出 |
| 重新打开 `.blend` 后不动 | 查看 Mesh Cache 引用路径，确认 PC2 仍在原位置 |
| 缓存回放与其他动画时间不一致 | 检查 FPS、起止帧和当前场景动画；不要直接改 PC2 二进制 |

该入口会先验证文件头、长度、计数、哈希、面、UV 和图片路径等，再创建场景对象。

**导出边界：**本插件的普通 FBX 导出没有专门把 PC2 自动转换为 FBX 可移植的骨架/形态键动画。保留缓存回放时应保留 `.blend + PC2 + 清单 + 图片`，不要把“FBX 文件生成了”当作顶点缓存动画已完整转换。

## 18. 导出 FBX、携带贴图和检查动画

### 18.1 导出前准备

1. 停止口型和眼球预览，恢复预期姿态。
2. 检查当前场景时间范围。
3. 保存 `05_待导出.blend`。
4. 切到物体模式。
5. 取消其他选择。
6. 选择最终网格；使用图集时选 `_Atlas` 副本，不要把隐藏原模型也选进去。
7. 需要骨架时，把对应骨架也一起选中。
8. 排除测试快照、无关物体、备用角色和不需要的相机灯光。

导出按钮采用**仅导出所选对象**。它不会替你识别哪个副本是最终版，也不会在只选网格时保证自动补选完整骨架。

### 18.2 设置贴图与动画选项

展开 **设置与诊断**：

| 选项 | 默认 | 如何选择 |
|---|---|---|
| 导出 FBX 时嵌入贴图 | 关闭 | 移交到另一台电脑时可开启，并在目标软件检查提取结果 |
| 导出 FBX 动画 | 开启 | 静态模型不需要动画时关闭 |
| 导出全部兼容 Action（可能较慢） | 关闭 | 确实要分别导出全部兼容 Action 时再开 |
| 分别导出 NLA 片段 | 关闭 | 确实按 NLA 片段组织输出时再开 |

**两项“全部 Action/NLA”都关闭，不等于不导出动画。**只要“导出 FBX 动画”开启，仍会烘焙当前场景范围和当前活动动画。

如果场景里测试过很多动作，首次导出先保持全部 Action/NLA 关闭，减少误带动画和长时间烘焙。

### 18.3 执行导出

1. 在 **快速访问**点击 **导出 FBX**。
2. 选择输出目录，建议与源 FBX 分开。
3. 输入清楚的文件名，例如 `角色A_Atlas_Final.fbx`。
4. 确认导出。
5. 等待提示 **FBX 已写入**。
6. 在资源管理器中检查文件存在、大小非零、修改时间更新。

插件先导出到临时目录，再发布正式文件。覆盖同名 FBX 时，会在输出文件旁保留带 `.bak-时间-标识` 的旧文件副本。

不要因为长动画导出暂时没有响应就连续重复执行。结束后再检查日志和文件；失败时先保留原文件及临时证据。

### 18.4 图片如何随模型移交

**开启嵌入贴图：**

1. 使用已保存到磁盘的源图/图集图片。
2. 开启“导出 FBX 时嵌入贴图”。
3. 导出。
4. 在目标软件中检查图片是否被提取、材质是否正确重建。

FBX 携带图片不等于携带 Blender 的任意 Shader 节点图，特别是复杂程序材质。

**不开启嵌入贴图：**

1. 本插件当前导出使用**绝对图片路径**。
2. 在原电脑、原路径打开可能正常，换电脑或移动文件后可能丢图。
3. 移交时同时复制图片/图集目录，并在目标软件中重新定位图片。
4. 不要认为把 FBX 单独复制走就完成了贴图交付。

### 18.5 导出后的回读验证

1. 保留当前工作文件，另开一个干净的 Blender 文件/进程做检查。
2. 启用同一插件。
3. 使用“导入 BomberStudio 模型”导入刚导出的 FBX。
4. 对 Blender 自身导出的动画往返，设置 **动画帧偏移 = 0**。
5. 检查以下项目：
   - 网格数量和最终模型是否正确；
   - 没有重复导出隐藏原模型；
   - 比例、朝向、整体位置；
   - 骨架和蒙皮；
   - 形态键/口型名称与变化；
   - 材质、图片和透明；
   - 第一帧、中间帧、最后一帧。
6. 然后再导入真正目标软件，检查其 FBX 材质/骨架解释结果。

对另一个引擎的导入配置，不要只用 Blender 中“看起来正常”代替目标端验收。

## 19. 诊断日志、插件更新与两种回滚

### 19.1 出错时先导出诊断

1. 停止连续点击出错按钮。
2. 记下当前 Blender 完整版本、操作按钮、选中对象和关键参数。
3. 如场景已有变化，另存一个“问题现场”文件，不覆盖唯一正常版本。
4. 选中出问题的网格。
5. 展开 **设置与诊断**。
6. 点击 **导出兼容性与模型诊断**。
7. 点击 **打开日志 / 临时文件夹**。
8. 保存以下证据：

   ```text
   diagnostics.json
   bomberstudio.log
   last-import.json    （导入相关问题时）
   ```

诊断包含版本、导入器状态、所选网格的顶点/面/UV/形态键信息和丢失图片列表等。丢失图片列表可能包含整个当前文件中的其他图片，并不全属于所选网格。

### 19.2 日志一般看哪里

默认完整路径：

```text
D:\BomberStudioWork\临时文件夹\bomberstudio.log
```

1. 用文本编辑器打开。
2. 从文件末尾看最近一次操作。
3. 找具体图片名、物体名、材质名、缺少的 UV 层或异常堆栈。
4. 按本教程第 21 章对应现象处理。
5. 修复后在小范围选择上重试，再扩大范围。

批量操作中，前面对象可能已成功、后面对象才报错。不要把一个错误提示理解为所有对象一定自动事务回滚；先检查场景，再选择撤销或打开备份。

### 19.3 回滚模型：打开 `.blend` 备份

1. 先另存当前现场。
2. 点击 **文件 → 打开**。
3. 进入：

   ```text
   D:\BomberStudioWork\临时文件夹\backups
   ```

4. 选择操作前时间点的 `.blend`。
5. 检查对象、材质和形态键是否恢复。
6. 用新工作文件名另存，继续处理。

也可以打开自己保留的 `01_刚导入.blend` 等阶段文件。贴图和 PC2 依赖仍需保留。

**“还原上一次插件备份”不是恢复模型按钮。**它恢复的是插件代码，流程见第 19.6 节。

### 19.4 手动检查插件更新

1. 展开 **检查版本更新**。
2. 查看当前版本。
3. 1.1.1 起默认仓库为 `Hoshino486/BomberStudio_Blender`；旧场景的空字段也使用此默认值。
4. 字段可自定义，支持 `owner/repo` 和完整 GitHub 地址，如 `https://github.com/Hoshino486/BomberStudio_Blender`；非空自定义值不会被默认仓库覆盖。
5. 点击 **手动检查本插件更新（15 秒超时）**。
6. 查看状态信息：发现新版本、已是最新正式版、本地版本高于已发布版本，或版本标签待人工核对。
7. 需要更新时点击 **打开 GitHub 发布页 / 下载更新**，从 Release 的 Assets 下载 Universal ZIP，再按下一节安装。

不要填写 MIMIBlender 或 Cats 仓库期待更新本插件，它们不是同一个安装包。检查只查询远端版本元数据，不会自动下载安装；比较成功不代表已经完成升级。

1.1.0 只接受简写，粘贴完整网址会误报“尚未配置”。旧版先填 `Hoshino486/BomberStudio_Blender` 即可检查；
安装 1.1.1 后两种格式均可用。若本地 1.1.1 尚未作为正式 Release 发布，而远端仍是 1.1.0，本地领先提示是正常结果。
查询成功记录在临时目录的 `last-update-check.json`；失败不会覆盖上次成功记录。详细错误分类见 [更新检查](./更新检查.md)。

若 Blender 关闭在线访问，会提示先处理首选项。一般模型操作、图集和 CSV 功能不需要因为更新检查而联网。

### 19.5 从本地 ZIP 安装更新

1. 保存所有工作文件。
2. 确认拿到的是 **BomberStudio Blender Bridge** 更新包，本版直接使用同一份 Universal ZIP。
3. 保留当前临时目录，不要在更新前后切换到其他路径。
4. 在 **检查版本更新**点击 **从本地 ZIP 安装更新（保留备份）**。
5. 选择更新 ZIP。
6. 等待“更新已写入；请重启 Blender”提示。
7. 关闭并重新打开 Blender。
8. 检查插件启用状态和面板中的当前版本。
9. 用一个测试工作文件验证导入/处理后，再继续重要项目。

更新会校验 ZIP 结构、路径、文件大小和 Python 语法，并保留旧版目录。**代码写到磁盘不代表当前进程已经加载新代码，重启是必要步骤。**

安装回执位置：

```text
D:\BomberStudioWork\临时文件夹\last-update.json
```

只在对应更新实际执行后才会有此文件。不要为了第一次安装而手动伪造回执。

### 19.6 回滚插件代码

1. 保存当前模型。
2. 确认临时目录仍是执行上次更新时使用的目录。
3. 在 **检查版本更新**点击 **还原上一次插件备份**。
4. 等待“旧版已恢复，请重启 Blender”提示。
5. 关闭并重开 Blender。
6. 检查恢复后的插件版本和功能。

这是针对**上次本地更新留下的安装目录备份**，不是任意历史版本管理器。第一次安装但从未更新，或备份目录/回执被搬走时，没有可用回滚记录。

成功回滚后不要把同一按钮当作无限往返切换开关；需要再升级时重新选择更新 ZIP。

### 19.7 临时文件夹哪些内容不要直接清空

| 内容 | 用途 |
|---|---|
| `backups` | 场景 `.blend` 回滚副本 |
| `bomberstudio.log` / `diagnostics.json` | 错误排查 |
| `last-import.json` | 最近一次模型导入记录 |
| `last-update.json`、更新备份目录 | 插件更新回滚 |
| 测试结果、验证日志 | 已交付版本的验证证据 |

图集通常在“输出”而不是“临时文件夹”。原始 PC2 缓存所在目录也可能不在临时目录中。

决定清理前，先确认工作文件是否仍引用相应文件；不要把“临时”理解成里面所有内容随时都可删。

## 20. 三个可以照着做的完整工作流

### 20.1 流程 A：只把 BomberStudio 角色正确导入并导出

适合第一次使用，不做骨架重构。

1. 按 Blender 版本安装正确 ZIP。
2. 打开 BomberStudio 面板，设置临时目录。
3. 在 BomberStudio 导出完整 FBX；按需开启材质、蒙皮、形态键和动画。
4. 保留整个导出目录。
5. 在 Blender 点“导入 BomberStudio 模型”。
6. 使用比例 1、材质旁文件开启、自动骨骼方向关闭。
7. 检查外观、UV、骨架和动画。
8. 有缺图先修路径；没有图片节点时再手动上贴图。
9. 查看 `last-import.json`，处理相关待检查项。
10. 保存 `01_刚导入.blend`。
11. 不使用没有明确需求的删组、归零和重命名按钮。
12. 选择最终网格及骨架。
13. 设置是否导出动画、是否嵌入图片。
14. 导出到新的 FBX 文件名。
15. 在干净文件回读验证。

**完成标准：**模型正确、贴图正确、该有的骨架和动画存在，且保留源导出目录和 `.blend`。

### 20.2 流程 B：把多材质模型整理成图集版本

1. 先完成流程 A 的导入和贴图检查，不急着导出。
2. 保存 `02_材质已修复.blend`。
3. 选择要处理的网格。
4. 可先用“合并相同材质”去除真正重复的绑定。
5. 到图集面板“生成材质列表”。
6. 首次只勾选少量普通材质。
7. 设置最长边 1024、间距 4、PNG、最大边长 4096。
8. 保持“创建副本并保留原模型”开启。
9. 如需要粗糙度/金属度/法线/发光且材质满足条件，开启 PBR。
10. 合并贴图。
11. 在原物体与 `_Atlas` 副本之间切换比较。
12. 检查输出图片和 `atlas.json`。
13. 如尺寸不足，降低单区域尺寸或分批，不删除原模型。
14. 验证表情和骨架仍正常。
15. 保存图集工作文件。
16. 只选择最终图集网格及其骨架，导出 FBX。
17. 保留并移交图集图片；按第 18 章检查目标端。

**完成标准：**外观符合预期、UV 正确、图片可找到、原模型仍可恢复。

### 20.3 流程 C：为已有角色补口型和眼球辅助

1. 导入包含蒙皮和 BlendShape 的模型。
2. 保存备份。
3. 检查现有骨名，只有需要时才做映射改名。
4. 选择脸部网格，确认三种基础嘴型。
5. 指定 AA/OH/CH，强度 1，生成 15 个口型。
6. 清零源表情键，逐项预览并做美术检查。
7. 停止口型预览。
8. 选中骨架，填真实头骨、眼骨和权重组名称。
9. 创建/定位眼骨，测试 ±10°，复位。
10. 检查是否需要为新骨骼设置父级。
11. 需要身高调整时，在中性姿态设置目标米数并验证。
12. 再测试一遍骨架、眼睛和口型。
13. 保存处理后的 `.blend`。
14. 选择角色网格和骨架导出。
15. 到 Unity 完成实际骨架/口型/眼球配置，再进行目标端测试。

**完成标准：**生成的数据存在且可用，不把“按钮执行成功”替代角色变形和目标平台检查。

## 21. 常见问题：按现象逐项排查

| 现象或提示 | 常见原因 | 按顺序处理 |
|---|---|---|
| 安装后搜不到插件 | ZIP 格式不匹配、选了外层文件夹或没安装成功 | 确认 Blender 完整版本 → 重新选本教程对应 ZIP → 查看安装报错 |
| 2.79 按 N 没有插件栏 | 入口在左侧工具架 | 鼠标进 3D 视图 → 按 T → BomberStudio |
| 新版 Blender 启用后看不到面板 | 当前不是 3D 视图、侧栏被收起 | 切 3D 视图 → 按 N → 滚动查找标签 |
| 提示类已注册/面板重复 | 同时启用多个安装格式或残留旧版本 | 保存工作 → 在首选项保留一套 → 重启；不要直接删除不明插件目录 |
| “请先选中网格物体” | 只选了骨架、空对象或没有选择 | 回物体模式 → 在大纲选实际网格 |
| 操作只影响一部分材质 | 活动材质槽或图集勾选范围不对 | 核对材质槽 → 重新生成列表 → 明确点击目标图片 |
| 模型是灰色 | 仍在实体模式或材质没接图 | 先切材质预览 → 查图片节点及日志 |
| 模型粉紫色 | 外部图片路径失效 | 选网格 → 指定正确贴图目录 → 精确文件名重定位 |
| 身体/脸异常透明 | 数据 Alpha 被当成透明度 | 确认基础色图 → 开启忽略 Alpha → 重新应用并检查 |
| 头发透明没了 | 对需要透明的图忽略了 Alpha | 确认图片透明通道 → 关闭忽略 Alpha → 重新应用 |
| 花纹错位 | UV 层、平铺或偏移不对 | 保留原 UV → 看旁文件待检查项 → 核对对应 UV 层 |
| “材质未唯一匹配” | 导出名与 Blender 材质名不唯一 | 检查重复导入和材质重名 → 在干净文件单独导入 |
| 同名图片匹配歧义 | 搜索目录有多个同名文件 | 缩小目录到正确模型 → 保持源引用路径 → 查看日志 |
| 导入后没有表情键 | 源文件没导出 BlendShape，或选错网格 | 在所有脸部网格检查 → 回源端开启对应选项重新导出 |
| 报 ASCII FBX 不受支持 | 仍用旧版插件或 Blender 自带导入菜单 | 重启并确认 1.1.0 → 使用 BomberStudio 面板导入原文件；自带菜单应使用二进制副本 |
| ASCII 转换后报 Root_M 绑定错误 | 没加载包含骨骼兼容修复的新版 | 保留原模型 → 重启确认 1.1.0 → 用插件重新导入 → 查看 fbx_conversion 记录 |
| 导入器未安装/未启用 | 该格式导入器不可用 | 在首选项核对对应导入器；PMX/PMD 查 mmd_tools，VRM 查 VRM 插件 |
| 形态键修改器提示拓扑变化 | 修改器增删顶点/面或不在支持范围 | 保留原文件 → 改在合适副本流程处理，不强行覆盖形态键 |
| 提示前面存在保留修改器 | 修改器求值顺序会改变 | 检查栈前段、名称和可见性，不盲目移动 Armature |
| 顶点组位置匹配为 0 | 不在同一世界位置、容差不合适、无权重 | 对齐并检查变换 → 核对活动参考对象 → 小步调整容差 |
| 清理后角色不再跟随骨架 | 删除/改名了蒙皮组 | 停止后续操作 → 撤销或打开备份 → 使用适合当前组类型的按钮 |
| 分割没有新对象 | 只有一个分组或连通关系本就统一 | 核对分割方式、活动 UV 和权重共享关系 |
| 原模型不见了 | 图集/分割默认隐藏原模型 | 在大纲找到原名 → 恢复视图可见性；要渲染还需恢复相机图标 |
| 图集提示先生成材质列表 | 列表为空、材质已删除或全未勾选 | 重新选网格 → 生成材质列表 → 勾选 |
| 图集最大尺寸错误 | 区域太多/太大或超过总像素上限 | 降到 512 长边 → 分批 → 不盲目改成 8192 正方形 |
| 图集提示复杂节点/多 UV | 源材质不满足直接图像/常量要求 | 先烘焙/简化材质到统一 UV，再合并 |
| 图集后只有颜色没有原先高光 | 只输出了基础色或特殊通道不受支持 | 检查 PBR 开关和源节点 → 不把基础色模式当完整 Shader 烘焙 |
| 合并骨架提示源骨架含动画 | Source 有 Action 或 NLA | 先保留动画备份，再在明确只需静态骨架的副本上处理 |
| “已存在 vrc.v_*” | 曾生成过目标口型 | 回生成前备份重做，或先妥善处理原键/动画引用 |
| 口型预览叠加、嘴张得太大 | 原 AA/OH/CH 或驱动仍生效 | 源表情清零 → 停播放 → 处理驱动冲突 → 再逐项预览 |
| 眼睛不转、整张脸被拉动 | 骨名、权重组或实际权重不对 | 核对左右眼组与顶点分布 → 检查绑定 → 在小角度下测试 |
| 眼骨创建后朝向不符合预期 | 新骨骼只是基础轴方向 | 检查局部轴和角色朝向，在备份基础上做模型专用调整 |
| 身高数值与目测不一致 | 包围盒包括头发/鞋/配件，或场景单位不同 | 用中性姿态 → 排除其他模型 → 检查单位和参与网格 |
| CSV 中文乱码 | 文件编码不是 UTF-8 | 另存 UTF-8 → 保留英文表头和逗号 → 再导入 |
| CSV 只想改物体却改了别的同名数据 | 使用了“全部”范围，kind 不做过滤 | 回备份 → 按类型分范围/分文件执行 |
| PC2 不动或校验失败 | 缓存路径变化、清单与文件不是同一批 | 保留完整导出目录 → 检查 Mesh Cache 路径 → 重新导出完整缓存 |
| FBX 文件里少了骨架 | 导出时没选骨架或源模型本无骨架 | 回场景检查绑定 → 同选网格和骨架 → 重新导出新文件 |
| FBX 换电脑后丢图 | 关闭嵌入时用了绝对图片路径 | 移交图片并重定位，或重新导出带嵌入图片的版本 |
| FBX 导出很慢 | 大场景、长时间范围、全部 Action/NLA | 只选目标 → 缩小正确时间范围 → 关闭不需要的全动作选项 |
| 回读动画差一帧 | 导入帧偏移不一致 | Blender 自身导出回读时显式设 0 |
| 检查更新提示未配置仓库 | 当前没有公开发布地址 | 保持空白正常使用；拿到本插件更新 ZIP 后本地更新 |
| 插件回滚找不到备份 | 没执行过本地更新、临时目录改变或备份缺失 | 回到原临时目录检查回执；恢复场景应打开 .blend 而不是点插件回滚 |

### 提交问题时一起提供什么

建议包含：

1. Blender 完整版本和 Windows 版本。
2. 使用的 ZIP 文件名、插件版本。
3. 点击的面板/按钮名称。
4. 当时的模式、选中对象、活动对象和相关参数。
5. 预期结果与实际结果各一句话。
6. 完整错误文字、`diagnostics.json`、日志末尾相关段落。
7. 问题只发生在一个模型还是所有模型。

报告可能包含本地路径和素材名称；对外分享前检查其中是否有不想公开的内容。
